# Agent Mesh v2.1.0 — scope notes (honest list)

What was scoped down, adjusted, or left unverified in v2.1.0, and why.
Nothing here is hidden: if it isn't listed as done in the CHANGELOG,
it is listed here.

## Adjusted existing tests (2)

- `tests/test_phase2.py` — `EXPECTED_TOOLS` gained `mesh_handover_log`.
  The phase-2 test pins the MCP tool set by exact equality; v2.1 adds
  a ninth tool by design (handover filing), so the expectation grew
  with it.
- `tests/test_phase5.py` — the version pin moved `2.0.1` → `2.1.0`.
  That test exists precisely to force every version surface to agree
  at release time (it was bumped the same way for v2.0.1).

## Scoped-down / design decisions

- **Pack formats `claude-code` and `cursor` are byte-identical to
  `mcp`.** Claude Code, Cursor and generic MCP clients genuinely
  consume the same `mcpServers` JSON schema; the formats differ in
  where the JSON gets pasted, which PROTOCOL §7.5 documents. Inventing
  different JSON would have been theatre.
- **Presence keeps the stored `status` field.** `presence` is the new
  computed field and is what the GUI shows; `status` remains so
  heartbeats can still report `busy` and older clients don't break.
  The dashboard "busy" count is stored-`busy` among presence-online
  agents.
- **Brokered `use` of an API credential returns a decision, not a
  proxied call.** That is exactly what v2.0's broker flow does
  (`use_check`); v2.1 extends the same flow to typed credentials and
  adds connection-details-only responses for login/ssh. No new proxy
  was built.
- **Handover export is per-node.** Each node maintains its own
  `HANDOVER-<node-name>.md` from the entries filed with it. Merging
  handover files across paired nodes was not built.
- **The handover CLI lives in `agent_mesh/handover.py`** as an
  appended entry point; the v1 functions in that file are untouched
  (the v1 CLI in `agent_mesh/cli.py` still owns the v1 `handover`
  subcommand for pack compilation).

## Not verified on real hardware (no such machines in the build env)

- `install-windows.ps1` and `install-macos.sh` were written carefully
  and reviewed, but not executed — there is no Windows or macOS
  machine in this environment. The Linux installer mirrors the live,
  verified PC setup (systemd --user unit + desktop launcher) but was
  not run here, because v2.1 was built code-only: **no live node was
  redeployed or restarted.** The live PC/VM nodes still run v2.0.1
  until a redeploy is ordered.
- The browser extension was validated as Manifest V3 JSON + file
  contract by tests, not loaded into a real browser.
- The PWA service worker / manifest were served and checked over
  HTTP; the install prompt was not exercised on a real phone.
- Shell installers pass `bash -n`; the PowerShell script is
  syntax-reviewed only (no PowerShell in this environment).

## Known limits carried over from v2.0 (unchanged)

- Peer traffic is HMAC-authenticated, **not encrypted** — pair only
  over LAN/Tailscale. No TLS was added in v2.1.
- The Tauri desktop app remains an uncompiled scaffold (no Rust
  toolchain in the build environment); the PWA is the installable
  app story for v2.1.
- Vault master key still comes from env / a 0600 file (no OS
  keystore integration).
